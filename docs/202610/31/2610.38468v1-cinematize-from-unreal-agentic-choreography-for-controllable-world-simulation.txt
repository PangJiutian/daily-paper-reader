ABSTRACT
Controllable world simulation requires more than visually plausible frames: scenes must retain
persistent state, coordinated actions, and editable temporal structure. Generative world models offer
flexible visual synthesis, but their outputs do not always expose the objects and transitions needed for
precise revision. Graphics engines provide executable state and direct control, yet translating language
into valid operations requires specialized knowledge of assets, geometry, and interdependent APIs. We
present CINEU (Cinematize from Unreal), an agentic system for language-driven world orchestration
and cinematic choreography within Unreal Engine. From a code-based world modeling perspective,
an Unreal project serves as a persistent, inspectable world representation, while agent-generated
code specifies operations whose effects can be executed and verified. CineU combines hierarchical
orchestration, cascaded asset retrieval and geometry-constrained placement, capability-aligned code
synthesis, and multi-stage verification with localized repair. Shared scene and timeline context
coordinates entities, actions, camera trajectories, and shot boundaries while supporting dependency-
aware revisions. Experiments on scene construction, selective editing, multi-shot cinematography,
and component ablations show how specialized execution knowledge and engine feedback improve
task completion and targeted recovery. CineU illustrates how executable world state can complement
learned visual generation to support controllable and revisable simulated worlds.
Keywords agentic systems; code-based world modeling; executable world state; controllable simulation; graphics
engines.
1
Introduction
Building a controllable dynamic world requires more than generating visually plausible frames. A simulated scene
has persistent entities, spatial relationships, actions, camera parameters, and temporal dependencies that must remain
consistent as the world evolves. Graphics engines provide explicit control over these structures and support programmatic
simulation [1, 2]. They also support cinematic previsualization, where changes to scene geometry and camera motion
must be coordinated [3]. However, translating a semantic request into a sequence of valid engine operations remains
labor intensive and requires specialized knowledge.
Generative foundation models offer a complementary capability. Image, video, and interactive-world models synthesize
rich visual outputs from high-level descriptions [4–7]. Graphics engines instead maintain addressable actors, asset
bindings, transforms, animation tracks, and camera keyframes. These representations enable precise execution and
revision, but expose a large and interdependent action space. A generated video may communicate the intended
appearance of a scene without providing an executable representation of its entities and events. Conversely, an engine
script may execute without realizing the intended composition. Code-based world models suggest making state and its
changes explicit in executable programs, rather than relying only on visual outcomes [8–10]. Here, the central challenge
is to connect flexible semantic reasoning with controllable, verifiable operations over a persistent engine world.

Recent language-agent systems combine reasoning, tool use, and feedback to execute complex tasks [11–13]. Language-
guided scene systems likewise translate semantic specifications into editable environments or motion programs.
UnrealLLM targets procedural scene generation in Unreal Engine [14]; LAMP produces explicit object and camera
trajectories [15]; and PrevizWhiz combines rough 3D layouts with video-based previsualization [3]. Camera-conditioned
video generation further supports geometrically specified viewpoints [16, 17]. These approaches motivate a more general
question: how can an agentic system coordinate scene construction, temporal control, and subsequent modifications
within the same executable world?
The difficulty lies in dependencies between operations. Replacing an actor may affect its support geometry, animation
compatibility, and camera framing. Walking requires the actor’s displacement and animation playback to agree in time.
A dolly zoom couples camera distance and focal length; valid values for either parameter alone do not guarantee the
desired effect. An execution error can also be localized to one operation even when previous operations have produced
correct scene state. A useful agentic architecture must therefore reason about task order, shared resources, cross-track
constraints, and the evidence needed to validate the resulting engine state.
We introduce CINEU (Cinematize from Unreal), an agentic system for controllable world simulation grounded in
Unreal Engine. We formulate a language instruction as a dependency graph of engine operations and execute it through
specialized agents that share project and timeline context. The system supports two connected capabilities: world
orchestration, which constructs and selectively modifies environments, entities, appearances, and actions; and cinematic
choreography, which coordinates camera motion, lens control, actor animation, and multi-shot sequences. The output
is a persistent Unreal project rather than an isolated rendered sequence. Unlike systems that infer world dynamics or
train a new rendering model, CINEU uses generated code to control the state and capabilities of an existing simulation
engine.
The architecture combines four mechanisms. First, hierarchical orchestration separates environment, entity, spatial,
and Sequencer responsibilities while preserving the dependencies between them. Second, cascaded asset retrieval
and geometry-constrained placement connect semantic descriptions to compatible resources and spatially feasible
configurations. Third, capability-aligned code synthesis instantiates verified engine patterns using the current project’s
object references and timing constraints. Fourth, verification-grounded reflection checks generated operations before
execution, traces their runtime behavior, inspects the resulting engine state, and repairs the responsible function where
possible. Together, these mechanisms connect semantic planning, code generation, geometric reasoning, and execution
feedback without assuming that a model’s stated result reflects the actual simulator state.
An important consequence is that the scope of a modification depends on the relations it must preserve. Changing a
material can leave geometry and timing untouched. Replacing an entity may require a placement update to preserve
support contact, while changing an animation may require re-aligning displacement and playback. The same dependency
structure guides both requested modifications and error recovery. This gives the system an explicit representation of
which operations can be changed independently and which must be coordinated.

We study CINEU through compound scene and camera instructions, selective revisions, multi-shot examples, and
component ablations. The latter show task completion of 47.8% with specialized knowledge compared with 18.4%
without knowledge, and 47.8% with multi-stage verification compared with 16.8% without verification. Function-level
repair achieves 47.8% completion compared with 38.1% under full regeneration in the reported configurations. The
qualitative examples illustrate the relationships behind these results, including camera and lens coupling, animation
synchronization, and scene-preserving revisions. Section 6 provides the evaluation details and limitations.
Our contributions are threefold:
• An engine-grounded agentic formulation of world simulation. We map language instructions to dependency-aware
operations over persistent scene and timeline state, supporting both construction and selective revision.
• A coordinated architecture for executable choreography. Hierarchical agents, cascaded retrieval, spatial constraints,
capability-aligned code generation, and verification-guided local repair connect specialized operations through shared
execution context.
• An empirical analysis of control and recoverability. Cinematic examples and component ablations characterize
cross-track synchronization, revision dependencies, the effect of specialized knowledge, and the contribution of
verification and targeted repair.
Rather than replacing a graphics engine with a learned simulator, CINEU uses agentic reasoning to access and coordinate
its explicit controls. This combination offers a practical route from high-level instructions to worlds whose scene state,
timing, and execution outcomes remain inspectable and revisable.

Related Work
2.1
Agentic Orchestration and Specialized Execution
Language-based reasoning and agentic execution provide complementary building blocks. Chain-of-thought prompting
and Graph of Thoughts organize reasoning steps [18, 19], while ReAct interleaves reasoning with environmental
actions [11]. Mindstorms explores natural-language societies of interacting modules [20]. Multi-agent frameworks
develop these ideas through role-playing communication in CAMEL [21], expert collaboration in AgentVerse [22],
conversational composition in AutoGen [23], and structured software-development processes in MetaGPT and Chat-
Dev [12, 24]. Work on scaling collaboration and Graph-of-Agents further examines how communication structure and
agent selection shape joint problem solving [25, 26].
Automation can also operate on the workflow itself. Promptbreeder and optimization by language models modify
prompts [27, 28]; GPTSwarm represents language agents as optimizable graphs [29]. Automated Design of Agentic
Systems and AFlow search over agent implementations and workflows [13, 30], while Archon searches compositions of
inference-time techniques [31]. The Workforce architecture separates planning, coordination, and tool-using workers;
OWL trains its planner through reinforcement learning [32]. These approaches motivate explicit orchestration, but
optimizing a task-solving workflow differs from preserving validated scene state while applying a constrained update.
Domain-specific systems illustrate why execution context matters. CogAgent addresses visual GUI operation [33];
MobileExperts and Mobile-Agent-v2 organize mobile-device operations through specialized agents [34, 35]; and web
agents with world models use environment dynamics for navigation [36]. Data Interpreter, natural-language-to-SQL
methods, and Trade in Minutes target data analysis, database access, and financial decision workflows, respectively [37–
39], while Z-AXIS applies agentic reasoning to enterprise evaluation [40]. In mathematical tasks, problem-understanding
methods and DeepSeek-Prover specialize reasoning for word problems and formal proofs [41, 42]. Their shared
relevance is the need to connect language to domain-specific objects, tools, and validity conditions; their task outcomes
are distinct from cinematic authoring.
Code capability is another separate concern. AlchemistCoder develops code-model capability through hindsight
tuning [43], whereas LiveCodeBench evaluates code generation through executable tasks [44]. In CINEU, a generated
program is an intermediate operation over a persistent scene. Correct API use must therefore be coordinated with asset
bindings, spatial relations, and shared timeline state. Our hierarchy follows these editable dimensions, and its shared
context connects operations whose outputs must agree.
2.2
Memory, Retrieval, and Verification-Guided Repair
Persistent context and retrieved knowledge serve different roles. InfLLM addresses efficient access to long-context
information [45]; G-Memory organizes cross-trial collaboration histories for multi-agent systems [46]. MindSearch

distributes information seeking and integration across agents [47]. CINEU separates a library of reusable engine patterns
from the current project’s realized state: a valid code pattern does not identify which actor, binding, or timeline a new
operation must modify.
Retrieval itself does not establish correctness. Self-RAG learns to retrieve on demand and uses reflection tokens to
assess retrieved passages and generated output [48]. In an engine-grounded task, the corresponding distinction is
between retrieving a relevant template and verifying its instantiated effect. The former supplies a candidate operation;
the latter requires execution feedback and inspection of the resulting world.
Self-Refine and language-model self-debugging use feedback to revise an initial output [49, 50]. Debug like a Human
emphasizes stepwise runtime verification for program repair [51]. Analyses of verification-based test-time computation
and faulty-agent collaboration make feedback quality and error propagation explicit research concerns [52, 53]. CINEU
applies staged checks to generated engine operations and directs revision toward the failing function. The resulting
repair boundary is consequential: repairing a camera operation should retain valid scene construction whenever the
affected operation can be isolated.
2.3
World Models and Executable Simulation
World simulation encompasses several representations with different uses. Dreamer and its subsequent world-model
developments learn dynamics for behavior learning [54, 55]. Learning Interactive Real-World Simulators and Genie
generate interactive environments from learned visual priors [7, 56]. Diffusion-based game engines and DIAMOND
model visual dynamics [57, 58]; GEM adds controls over ego-motion, object dynamics, and scene composition [59].
DINO-WM uses pretrained visual features for planning [60], and exploration-driven generative environments examine
interaction with generated worlds [61]. These systems relate visual state to actions, rather than treating simulation as
rendering alone.
Code-based world modeling makes state changes explicit through executable representations. WorldCoder writes
programs to model an environment from interaction [8]; Code World Models for General Game Playing synthesizes
transition rules that can be used by planners [62]. Code2Worlds generates simulation code for dynamic 4D scenes and
refines it through physics-aware feedback [9]. The Code World Model framework separates persistent state evolution,
maintained by a coding agent, from video-based visual realization [10], while Code-as-World discovers executable
physical representations from multimodal observations [63]. These approaches share a commitment to executable
structure but differ in how dynamics are obtained and how worlds are rendered or controlled.
Engineered platforms expose a complementary form of control. UnrealCV, PUG, BEHAVIOR Vision Suite, and
Unreal-MAP support programmatic observation, controllable synthetic data, or multi-agent simulation [1, 2, 64, 65].
BEHAVIOR-1K supplies a broad embodied-activity setting [66]. Application-specific work includes synthetic person
re-identification in UnrealPerson [67], closed-loop sensor simulation in UniSim [68], and generative autonomous-
driving modeling in GenAD [69]. Dataset customization and perturbation offer further approaches to visual-data
construction [70, 71]. These applications motivate explicit scene and action control, while CINEU focuses on the
executable operations that construct and revise such scenes.
The distinction between learned and executable worlds is not binary. Video2Game and PhysGen3D reconstruct
interactive environments from visual input [72, 73]. CINEU does not infer new transition rules or train a visual world
model. Instead, it uses code to orchestrate the existing abstractions of a graphics engine, retaining an authored scene and
timeline. Its focus is how language-driven operations compose, remain revisable, and recover from execution failures in
that persistent representation.
2.4
Language-Guided Scene Construction and Editing
Language-driven scene construction already connects semantic specifications to structured environments. Holodeck
generates embodied 3D environments using language guidance [74], and ChatScene uses domain knowledge for
safety-critical driving scenarios [75]. UnrealLLM is especially close to our implementation setting, combining language
agents, domain knowledge, and procedural content generation in Unreal with editable engine representations [14].
These systems establish important precedents for language-mediated access to simulation and scene-building tools.
Recent agentic methods further integrate spatial and visual feedback. Scenethesis combines language and vision
for scene generation [76]; spatially contextualized VLMs maintain geometric and relational context for generation
and downstream editing [77]. SAGE couples scene generators with critics for task-conditioned, simulation-ready
environments [78]. Edit-As-Act uses goal-regressive planning and geometric validation for selective indoor-scene
editing [79]. CINEU builds on this broader direction but concentrates on the coupling between scene changes and

2.5
Controllable Visual Generation and Cinematography
Controllable synthesis offers a range of ways to express visual intent. GLIGEN grounds image generation in spatial
conditions [80], Composer combines multiple conditions [81], and ControlNet adds structural conditioning to diffusion
models [82]. DreamBooth supports subject-driven generation [83], while InstructPix2Pix expresses edits through
language [84]. Seedream develops general image synthesis [4], and Generative Photography studies scene-consistent
camera control [85]. These approaches distinguish controls over identity, appearance, layout, and viewpoint, dimensions
that also need distinct revision targets in a 3D authoring tool.
Video systems add temporal dependencies. Caption-based video summarization also connects temporal media to
language [86]. AnimateDiff animates personalized image-generation models [87], and VideoComposer combines
motion and other conditioning signals [88]. Snap Video develops spatiotemporal modeling [89]; Collaborative Video
Diffusion addresses consistency across camera-controlled videos [90]; and StreamingT2V extends text-conditioned
video generation over time [91]. HunyuanVideo, Wan, Seedance, and Veo provide general text-conditioned video
synthesis [5, 6, 92, 93]. Analysis from a physical-law perspective highlights that visual plausibility and physical
consistency are separate properties [94].
Camera and geometric control extend beyond prompts. AC3D analyzes camera control in video diffusion transform-
ers [95]; Gen3C supplies 3D-informed guidance [16]; and Generative Rendering uses a 4D representation to guide
video synthesis [96]. Unified Camera Positional Encoding and 3D Scene Prompting encode explicit camera or scene
conditions [17, 97]. Infinity-RoPE supports action changes and cinematic cuts during long video rollout [98], while
DragStream enables streaming drag-based manipulation [99].
LAMP is particularly relevant: it translates language into a motion domain-specific language and deterministically
derives object and camera trajectories that guide video generation [15]. Building on this connection between language
and explicit motion, CINEU focuses on the persistent engine project in which assets, placement, animation bindings,
lens parameters, and shot boundaries are jointly represented, together with verification and function-level repair of
operations over that project. PrevizWhiz further demonstrates the value of combining rough 3D scenes and 2D video
with generative previsualization [3]. The design question is consequently which representation supports the creator’s
next decision: a generated preview can guide appearance, while an engine-native scene and timeline provide concrete
objects for continued revision.
2.6
Structured Editing and User Control
Interactive systems provide useful precedents for keeping generated results interpretable and revisable. Human–AI
interaction guidelines emphasize clear system behavior and correction [100, 101]; mixed-initiative interaction and the
COFI framework examine how automated contributions are combined with user decisions [102, 103]. In language and
visualization systems, Wordcraft, AI Chains, and HAIChart expose intermediate steps or alternative outputs that can be
inspected and revised [104–106]. Studies of control across co-creation phases further suggest that the desired scope of
intervention changes as a result becomes more complete [107].
Spatial authoring systems provide a closer comparison. VRCopilot uses intermediate wireframes for scene layout [108];
Dreamcrafter supports 3D editing through proxy representations [109]; and ImaginateAR combines generated assets
with scene understanding and manual refinement [110]. Generative Agents instead simulates character behavior through
memory, planning, and reflection [111]. These works motivate preserving addressable structure after generation. Our
focus is on the execution dependencies that make such structure usable in a graphics engine, particularly the coupling
of actors, transforms, animation tracks, and camera timing.

4
Task Representation and Execution Workflow
CINEU converts a natural-language specification into an ordered set of operations over a persistent Unreal project. Its
workflow maintains separate representations for the requested task, the realized engine state, and the execution context
that connects them. This separation supports incremental changes, cross-track coordination, and diagnosis when an
operation does not produce the intended result. Section 5 describes the corresponding agents and middleware; Section 6
examines their behavior in scene and camera tasks.
4.1
Task, World State, and Execution Context
The task specification identifies entities, spatial relationships, actions, camera behavior, and relevant constraints.
The world state consists of realized actors, transforms, assets, material assignments, and Sequencer tracks. The
execution context holds task dependencies, engine object references, timeline identifiers, and diagnostic feedback.
These representations are related but not interchangeable: an accepted instruction does not imply that the corresponding
operation has completed in the engine. In this executable-world view, agent-generated code proposes an intervention,
while Unreal performs the state transition. The stored project state, rather than the agent’s textual prediction, is the
basis for subsequent operations.
The operation types mirror the engine’s controllable units. Environment tasks configure levels and atmosphere;
entity tasks retrieve and import resources; spatial tasks satisfy placement constraints; action tasks bind animation
and displacement; and camera tasks specify framing, lens values, trajectories, and cuts. Each type has specialized
implementation requirements. Their inputs and outputs are nevertheless coupled, since an animation requires a
compatible actor and a camera trajectory depends on the subject’s actual position.

4.2
Execution Sequence
Decomposition and grounding.
An orchestration agent maps the instruction to a dependency graph of environment,
entity, placement, action, and camera subtasks. Asset retrieval first uses the validated local cache and then searches
external resources if necessary. Middleware queries the active project for object references, support geometry, and
timeline state. These queries replace implicit assumptions about the scene with concrete engine context.
Synthesis and execution.
Specialized agents instantiate capability-specific code patterns. The Sequencer agent estab-
lishes a shared timeline, and camera, animation, and transform sub-agents operate on its track references. Middleware
performs static checks, executes the generated functions, and collects runtime traces and engine-state feedback. A
successfully executed function can still violate a spatial or temporal requirement, so validation extends beyond syntax
and runtime completion.
State inspection and revision.
The resulting actors, keyframes, and camera tracks persist in Unreal. Subsequent
instructions can target a material assignment, entity binding, or track without reconstructing the entire world. The
viewport shows the rendered state, while Sequencer and execution traces expose the structures and operations relevant
to validation or recovery.
4.3
Local Updates and Dependency Scope
A modification has an explicit target and an associated dependency scope. Selective invocation addresses the target
resource; shared execution context identifies other state that must be reconsidered. An animation replacement may
require displacement alignment, and an entity replacement may require updated support constraints. By contrast, a
material-only change can usually leave geometry and timing unchanged. The system therefore aims to preserve valid
relationships and unrelated operations rather than enforce strict parameter-level isolation.

4.5
Example: A Rooftop Sequence
The rooftop instruction in Figure 1 combines a rooftop character, an action, a dolly zoom, and an orbit. The task graph
orders scene construction, entity retrieval, placement, animation binding, and camera segments. The spatial agent
derives placement from the building and actor bounds; Sequencer supplies a shared time reference for the action and
the two camera movements. The dolly zoom couples focal length with camera distance, while the orbit changes the
viewpoint around the subject.
This example illustrates why correct isolated operations are insufficient. Camera parameters depend on the realized
actor position, shot segments must agree with sequence timing, and a failed camera function should not invalidate
successful environment construction. The same stored dependencies support targeted modifications and function-level
repair, with verification applied to the affected state.

System Design and Implementation
5.1
Architecture and Responsibility Boundaries
CINEU separates orchestration, specialized generation, middleware, and engine execution (Figure 2). The architecture
follows the task and state representations in Section 4. It assigns operations to appropriate specialized capabilities while
maintaining shared world state and timeline references.
Task model.
We model the execution setting as a tuple (T , E, A, O, W). Here, T is the natural-language task
specification encoding scene, action, and camera intent; E is the graphics-engine environment; A is the agent pool; O is
8


Cinematize from Unreal
the set of atomic engine operations exposed through the system; and W is the realized world state, including actors,
transforms, animation bindings, camera parameters, and Sequencer tracks.
Orchestration agent.
The orchestration agent interprets the task specification, decomposes it into subtasks, identifies
precedence relationships, and manages asset retrieval. Its dependency graph determines the order and context of
specialized invocations. A camera operation that follows a subject depends on the corresponding entity and placement
operations; animation and transform operations depend on the shared sequence initialization.
Specialized agent pool.
The environment agent configures the level and atmosphere. The entity agent imports and
integrates assets. The spatial agent determines transforms that satisfy relational and collision constraints. The Sequencer
agent initializes the timeline and coordinates camera, animation, and transform sub-agents. The separation limits
irrelevant task context, while parent-provided references and synchronization constraints connect work that must remain
coupled.
System middleware and backend.
Middleware provides file and process operations, backend interaction, code
validation, tracing, and two-version reflection rollback. Agent instructions use XML-formatted messages; parameters
and serialized state use JSON schemas. Unreal Engine, accessed through its Blueprint system and programmatic
interfaces, contains the realized actors, assets, and timeline. The implementation uses Unreal Engine 5.5 and earlier
versions described in the system configuration. We rely on engine queries for realized state rather than treating a
model’s textual description as evidence that an operation succeeded.

5.2
Task Dependencies and Execution Context
The dependency graph G = (V, D) contains subtasks and precedence relationships. Typical subtasks include envi-
ronment configuration, entity import, placement, animation binding, transform animation, camera construction, and
shot coordination. Each subtask corresponds to a bounded set of engine operations. Their dependencies identify both
ordering requirements and information that one operation must supply to another.
Middleware retrieves project state and environmental attributes from Unreal to contextualize those subtasks. During
temporal authoring, the Sequencer agent provides a timeline reference, duration, and track allocation to its sub-
agents. The generated camera, transform, and animation functions inherit this context rather than independently create
incompatible sequence structures. State inspection after execution provides the next repair attempt with concrete
diagnostic information.
Selective invocation is grounded in subtask responsibilities and the current engine context. Cross-track relationships
are maintained through shared references and synchronization constraints; after a change, the affected operations are
checked against the requested scene and timeline relationships.
5.3
Cascaded Asset Retrieval
The local cache contains more than 300 validated assets, primarily sourced from Unreal Fab and Mixamo and annotated
with semantic tags and functional descriptors. Retrieval first matches the requested asset against this cache. When
no suitable local resource is found, marketplace search is invoked and refined using the engine version and project
constraints. Validated external assets are cached for reuse. The cache provides known compatible resources; marketplace
retrieval expands the set of realizable scene entities.

Verification operates at three stages. Static validation checks syntax, types, and API compatibility before execution.
Instrumented execution records calls, parameters, returns, and exceptions. Post-execution state inspection compares the
realized scene, transforms, tracks, and camera parameters with task expectations. These stages locate failures before,
during, and after execution. Section 6.1 separately defines the outcomes used to assess task completion.

7
Discussion
The results illustrate how agentic reasoning can be grounded in a simulator that exposes structured state. The relevant
technical properties are the addressability of generated objects, the dependencies between operations, and the reliability
of execution feedback. These properties determine whether a system can modify an existing world without losing
previously validated work.
7.1
Persistent State as an Execution Interface
Unlike a sequence of generated frames, an Unreal project retains explicit actors, transforms, animation bindings, camera
parameters, and temporal tracks. These objects provide targets for subsequent operations and diagnostics. A material
substitution can address a particular actor; a camera revision can address a specific track and interval. The rendered
viewport remains useful for inspecting appearance, but it does not replace the engine state needed to identify and modify
the operation that produced a result.
This distinction connects to work on editable intermediate representations in AI Chains, VRCopilot, and Dream-
crafter [105, 108, 109]. In CINEU, the intermediate representation is executable scene and timeline state rather than
only a visible plan or proxy. The resulting benefit is not that every requested edit is independent. It is that the system
can identify the objects, constraints, and functions implicated by the edit.
7.2
Update Locality Depends on Relationships
The selective-revision cases show that the scope of a modification cannot be defined solely by the resource named in the
instruction. A replacement entity may have different bounds and require a placement adjustment to preserve support
contact. A new animation must remain synchronized with the actor’s transform track. In contrast, a texture update can
preserve the existing motion and camera sequence. Table 2 makes these relationships explicit.
Locality is therefore relational: an update should preserve validated constraints while changing the smallest set of
operations needed to satisfy the revised instruction. This is also the rationale for combining capability-specific agents
with shared context. Specialized knowledge limits the API patterns considered by each agent; shared object and timeline
references maintain consistency across their outputs. The two mechanisms address different failure modes and should
not be conflated.
7.3
Verification, Recovery, and Their Boundaries
A syntactically valid program, a completed engine call, and a correct scene are different outcomes. Static analysis
checks the proposed operation; tracing reveals runtime behavior; and engine-state inspection evaluates observable
scene and timing constraints. Table 3 describes the evidence available at each stage. The ablations indicate that the
verification chain affects recovery even when first-attempt program correctness is unchanged across configurations.
18


Cinematize from Unreal
Function-level repair retains validated operations when the failure can be isolated. This reduces the scope of regeneration,
but its effectiveness depends on whether the diagnostic identifies the responsible function and affected state. Cross-track
errors may require coordinated updates, and an invalid asset or unresolved geometric constraint may not admit a local
fix. Moreover, state conformance is not equivalent to visual quality: a camera can satisfy formal parameter constraints
while producing an undesirable composition. The system checks operational requirements; choosing or revising an
artistic objective remains a separate decision.
7.4
Relation to Code-Based World Models
Executable world representations offer a way to make state changes inspectable and repeatable. CINEU adopts this
perspective at the control layer: it produces code that modifies a persistent world, but the world state and dynamics are
provided by Unreal rather than inferred from observations. This differs from learning a transition model or synthesizing
a new simulator. The distinction also defines a verification boundary. Successful code execution does not establish that
an agent has learned physical laws; it establishes only that the specified operations can be checked against available
engine state and task constraints. In this setting, the benefit of code is to expose editable objects, transitions, and their
dependencies for continued orchestration.
7.5
Limitations and Scope
The system depends on the availability and compatibility of its assets, templates, and Unreal interfaces. Axis-aligned
bounding boxes approximate support and separation but do not constitute a general contact or rigid-body physics
solver. Camera geometry uses simplified assumptions, and the reported configuration-level ablations do not establish
universal performance across all prompts, engines, or asset libraries. Reproduction depends on committed project state,
compatible engine versions, and deterministic components under fixed settings. Two-version rollback applies only to
the functions and state covered by the middleware.
Engine-grounded generation complements, rather than replaces, learned visual synthesis. Generated video can offer
richer appearance, while structured simulation supports explicit geometry, timing, and localized revisions. Combining
these strengths is a useful direction for future systems, but would require additional methods for transferring generated
content into compatible assets and executable state. Asset provenance, licensing, and potentially deceptive media uses
also remain considerations for deployment.
8
Conclusion
We introduced CINEU, an agentic system that translates language instructions into executable operations over persistent
Unreal Engine worlds. Its hierarchical orchestration coordinates asset retrieval, geometry-constrained placement,
animation, camera trajectories, and shared timelines. Capability-aligned code synthesis grounds operations in verified
engine patterns, while staged verification and function-level repair use execution feedback to recover from failures
without unnecessarily regenerating valid state. Scene construction, multi-shot examples, selective revisions, and
component ablations characterize the system’s controllability and recovery behavior. Viewed alongside code-based
world modeling, CINEU demonstrates an engine-grounded approach in which agent-generated programs control a
persistent world representation rather than replace the simulator’s dynamics. Precise world simulation requires more
than independent valid actions: it requires explicit dependencies and retained scene state so that operations remain
consistent across execution and revision.
