## 摘要
可控世界模拟不仅需要视觉上合理的画面，还要求场景保持持久状态、协调动作以及可编辑的时间结构。生成式世界模型提供了灵活的视觉合成能力，但其输出并不总能显式暴露精确修改所需的对象与状态转换。图形引擎提供可执行状态和直接控制，但将语言转化为有效操作需要关于资产、几何及相互依赖 API 的专业知识。我们提出 CineU（Cinematize from Unreal），一个在 Unreal Engine 中实现语言驱动世界编排与电影化编排的智能体系统。从基于代码的世界建模视角看，Unreal 项目可作为持久、可检查的世界表示，而智能体生成的代码则指定了其效果可被执行和验证的操作。CineU 结合了分层编排、级联资产检索与几何约束放置、能力对齐的代码合成，以及带有局部修复的多阶段验证。共享的场景与时间线上下文协调实体、动作、相机轨迹和镜头边界，同时支持依赖感知的修订。在场景构建、选择性编辑、多镜头电影摄影和组件消融上的实验表明，专门的执行知识与引擎反馈如何提升任务完成度和针对性恢复。CineU 展示了可执行世界状态如何补充学习式视觉生成，以支持可控且可修订的模拟世界。

## Abstract
Controllable world simulation requires more than visually plausible frames: scenes must retain persistent state, coordinated actions, and editable temporal structure. Generative world models offer flexible visual synthesis, but their outputs do not always expose the objects and transitions needed for precise revision. Graphics engines provide executable state and direct control, yet translating language into valid operations requires specialized knowledge of assets, geometry, and interdependent APIs. We present CineU (Cinematize from Unreal), an agentic system for language-driven world orchestration and cinematic choreography within Unreal Engine. From a code-based world modeling perspective, an Unreal project serves as a persistent, inspectable world representation, while agent-generated code specifies operations whose effects can be executed and verified. CineU combines hierarchical orchestration, cascaded asset retrieval and geometry-constrained placement, capability-aligned code synthesis, and multi-stage verification with localized repair. Shared scene and timeline context coordinates entities, actions, camera trajectories, and shot boundaries while supporting dependency-aware revisions. Experiments on scene construction, selective editing, multi-shot cinematography, and component ablations show how specialized execution knowledge and engine feedback improve task completion and targeted recovery. CineU illustrates how executable world state can complement learned visual generation to support controllable and revisable simulated worlds.

- **背景**：可控世界模拟不仅要生成视觉上合理的画面，还必须维持持久实体状态、空间关系、动作、相机参数与时间依赖，并支持后续精确修订。

  - 图形引擎（如 Unreal Engine）提供可执行状态、显式对象与直接控制，但把自然语言转换为合法的引擎操作序列需要资产、几何、API 依赖等专业知识，人工成本高。
- **核心挑战**：如何把灵活的语义推理与对持久引擎世界的可控、可验证操作连接起来，使场景构建、时间控制与后续修订在同一个可执行世界中完成。

- **充分性评估**：
  - **优点**：消融设计针对性强，能分别剥离"知识获取""验证深度""修复粒度"的贡献；指标分离首轮正确率与恢复过程，避免混淆首次合成与迭代修复。
  - **不足**：① 无标准 benchmark，任务集规模、样本量、随机种子与统计显著性均未报告，Table 4 为"配置级结果"，作者自称仅作描述性分析；② 与生成式视频模型的对比是定性的，无用户研究或量化偏好评分；③ 仅在 Unreal 单一引擎、单一资产库上评估，跨引擎/跨资产库泛化未知；④ 成功率 47.8% 的绝对值偏低，失败案例虽被归类但未系统统计各类失败占比；⑤ 公平性方面，生成基线未做同等工程化调优，比较维度（外观 vs 可控性）本身不完全对等，作者也承认二者互补。

## 6. 主要结论与发现

- **可执行世界状态是有效补充**：Unreal 工程提供可寻址的 actor、变换、动画绑定、相机参数与时间线轨道，使"修改某个对象/轨道"成为可能，这是纯生成视频所不具备的。
- **专门知识与验证显著提升完成度**：
  - 知识：无知识 18.4% → 统一库 31.2% → 能力对齐子集 47.8%（约为无知识的 2.6×）。
  - 验证：无验证 16.8% → 单阶段 29.5% → 多阶段 47.8%（首轮程序正确率恒为 56.2%，说明验证作用于**恢复**而非首次生成）。
  - 修复：函数级最小干预 47.8% vs 全量重生成 38.1%（+9.7 个百分点），精化轮数 5.6 vs 7.8。
- **依赖关系决定修改范围**：局部性由关系而非指令中命名的资源决定——纹理编辑范围窄，实体替换需重做放置，动画替换需重对时序。
- **验证边界清晰**：语法合法、调用完成、场景正确是三种不同结果；状态一致性不等于视觉质量，审美判断仍需人来完成。
- **与生成模型的定位**：生成模型提供外观先验，引擎原生场景与时间线提供可继续修订的具体对象，二者互补。

## 7. 优点

- **问题刻画清晰**：明确区分任务规格、世界状态与执行上下文三种表示，强调"指令被接受 ≠ 操作已执行"，方法论上严谨。
- **依赖感知的架构设计**：分层编排 + 共享上下文同时解决"专业隔离"与"跨轨一致"两个对立需求，Table 2 把修订依赖显式化，具有工程指导价值。
- **验证-修复闭环完整**：静态检查/运行时追踪/状态检查三阶段对应不同失败类型（Table 3），函数级局部修复 + 两版本回滚 + 有界迭代，避免"全量重来"。
- **几何与相机建模具体**：给出可执行的放置约束方程与推拉变焦耦合公式，而非停留在概念描述。
- **消融实验设计有针对性**：分别隔离知识、验证、修复三个变量，并区分首轮正确率与恢复能力，结论解释力较强。
- **定位诚实**：明确说明是引擎控制的补充而非替代学习式世界模型，并讨论了资产授权、潜在欺骗性媒体等部署风险。

## 8. 不足与局限

- **物理与几何近似**：使用轴对齐包围盒近似支撑与间隔，非通用接触/刚体物理求解器；相机几何基于固定主体、透视投影的简化假设，复杂场景下可能失效。
- **资源强依赖**：效果受限于资产可用性与兼容性、模板库覆盖度、Unreal 接口支持；不支持资产组合是潜在失败源；未解决"生成内容如何转为兼容资产"的迁移问题。
- **实验覆盖有限**：单一引擎、单一资产库、自建小规模任务集，无标准 benchmark、无统计显著性检验、无用户研究；47.8% 的绝对成功率说明仍有大量失败场景（无效放置、构图无信息、跨轨干扰）。
- **对比公平性存疑**：与 HunyuanVideo/Veo/Seedance/Wan 仅做定性对比，评估维度不对等；基线未做同等工程化适配。
- **失败分类未量化**：Figure 9 仅作示例性展示，未统计各类失败的比例与分布。
- **可复现性与成本**：依赖提交工程状态、引擎版本与确定性设置；未报告 LLM 调用成本与推理时延，实际部署成本不明。
- **应用限制**：资产来源与授权、生成内容的潜在欺骗性使用尚未解决；审美与创作意图的判断被明确排除在自动验证之外。
