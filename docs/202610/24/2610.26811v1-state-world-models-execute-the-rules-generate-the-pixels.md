## 摘要
现有的世界模型能够从单张图像生成以动作为条件的视频。许多工作关注相机运动，使用户能够探索生成的场景。然而，仅靠导航并不能确保动作遵循持续规则，当其结果取决于当前帧中不可见的状态时。我们提出 Stateful Harness，一个将世界演化与视频渲染分离的框架，以支持有状态且受规则支配的交互。它在指定规则下维护不断演化的世界状态，用冻结的视频模型渲染每个产生的事件，并利用生成的片段更新下一轮的世界状态。每一轮中，该框架解析用户选择的动作，并将产生的事件编译为指令，同时来自可编辑3D场景的预览片段提供空间和相机引导。为评估规则符合性，我们构建了 WorldState-Bench，一个包含50个反事实孪生对的基准，这些对共享初始帧和动作，但在隐藏状态和所需结果上不同。在仅规则提示下，11个被评估视频后端中最好的一个在32%的对中为两种情况生成所需结局。对于 MiniMax-H3，指定所需结局将该比率从32%提高到64%，而完整框架在相同冻结模型下达到92%。这些结果支持将规则执行与视频渲染分离，以处理具有隐藏状态的世界交互。

## Abstract
Existing world models can generate action-conditioned video from a single image. Many focus on camera movement, allowing users to explore the generated scene. However, navigation alone does not ensure that an action follows persistent rules when its outcome depends on state that is invisible in the current frame. We present Stateful Harness, a framework that separates world evolution from video rendering to support stateful and rule-governed interaction. It maintains an evolving world state under specified rules, renders each resulting event with a frozen video model, and uses the generated clip to update the world state for the next turn. At each turn, the harness resolves the action selected by the user and compiles the resulting event into an instruction, while a preview clip from an editable 3D scene provides spatial and camera guidance. To evaluate rule compliance, we build WorldState-Bench, a benchmark of 50 counterfactual twin pairs that share an initial frame and action but differ in hidden state and required outcome. Under rule-only prompting, the best of the 11 evaluated video backends produces the required endings for both cases in 32% of pairs. For MiniMax-H3, specifying the required endings raises this rate from 32% to 64%, while the full harness reaches 92% with the same frozen model. These results support separating rule execution from video rendering for world interactions with hidden state.

## 1. 核心问题与研究动机

- **背景**：视频生成模型已能根据单张图像生成动作条件视频，交互式世界模型（Genie 系列、Oasis、Matrix-Game、Astra 等）进一步支持用户通过导航/动作探索生成场景。
- **核心缺口**：导航可控 ≠ 行为受规则约束。当动作结果依赖于**当前画面中不可见的隐藏状态**（如是否持有钥匙、元素属性、好感度）时，纯视频模型无法保证：
  - 同一帧 + 同一动作，在不同隐藏状态下应产生**不同**结局；
  - 动作的后果能**跨轮次持续**（状态持久化）；
  - 结果符合预先定义的**可执行规则**。
- **典型失败现象**（图 2）：反事实孪生对中，`has_key=false` 与 `has_key=true` 共享首帧和动作，但未包装的视频模型对两者都“打开箱子”，违反规则——作者称为 **Twin Collapse（孪生坍缩）**。
- **现有工作的不足**：PWM、Code World Model、StatePlay、WorldMind 等虽引入显式状态，但依赖定制像素级条件、微调渲染器或从像素反推状态；其评估多针对特定机制，**未验证“冻结视频模型能否忠实渲染由新规则规定的隐藏状态后果”**。
- **核心主张**：让状态转移具有**权威性**，把“世界如何演化”与“像素如何生成”解耦。

## 2. 方法论：STATEFUL HARNESS

### 2.1 核心思想
在**冻结的视频模型**外围加一层“有状态运行时（harness）”，把一次交互拆成三段：
1. **规则执行**（决定“发生了什么”）；
2. **视频渲染**（决定“看起来怎样”）；
3. **视觉观察**（从生成片段回读可观测状态，闭环更新）。

### 2.2 状态表示
- 世界状态 `s_t = (z_t, u_t) ∈ S_sem × S_sp`：
  - **语义账本 `z_t`**：资源、实体属性、进度、态度、终止状态等（帧内不可见）；
  - **空间状态 `u_t`**：可编辑实体布局、尺度、相机轨迹（“黏土模型” clay model）。
- 闭环更新：`s_{t+1} = H_R(s_t, a_t, o_{t+1})`，规则程序 `R` 全程固定。

### 2.3 Stage 0：世界构建
- **编码智能体**（GLM-5.3）依据自然语言世界描述，写出小型类型化语言的可执行游戏定义：状态 schema、可用动作、规则（guard + effect）、事件、目标、视觉语义；交互前校验并冻结。
- **首帧与空间状态**：用前馈几何模型（VGGT）把首帧提升为实例框 + 地平面的无纹理可编辑 3D 场景（clay model）；部署版用 WildDet3D（基于 SAM3）+ LingBot-Depth 做单主体定位，Blender 渲染与输入视角像素对齐的预览。
- **语义状态**：可序列化的类型化字段账本；孪生对通过不同隐藏初值 `z_A ≠ z_B` 而保持首帧与空间布局一致。

### 2.4 Stage 1：单轮生命周期（算法 1）
1. **规则结算**（渲染前完成，规则具有最终裁决权）：
   `(z̄_{t+1}, ε_t, e_t) = τ_R(s_t, a_t)`，`ū_{t+1} = apply(u_t, ε_t)`
   得到临时语义状态、空间编辑脚本、事件。
2. **可选神经核 ρ**：生成对白/叙述，但经 schema 校验、数值裁剪、有界重试、规则默认回退，保证其支持集被限制在规则允许集 `A_τ(s,a)` 内（式 3），**只能改变表达方式，不能改变规则规定的转移**。
3. **空间引导**：对 clay model 应用编辑，程序化相机渲染出预览片段 `r_t`（提供布局与相机轨迹，不提供外观）。
4. **指令编译**：VisualScript 编译器把结算后的事件编译为带槽位的类型化脚本（actor / action / target / reaction / dialogue / effects / end state / shots / stability 等），再由固定编译器映射为文本 `p_t`；相同输入产生相同指令（确定性）。指令中显式声明预览仅为**布局参考**，避免后端复刻黏土材质。
5. **冻结渲染**：`v_{t+1} = V_θ(p_t, r_t, f_t)`，`f_{t+1} = last(v_{t+1})`；权重全程冻结，仅用后端原生 text / image / video reference 接口，每轮一次生成请求。
6. **视觉观察与状态更新**：VLM `O_ψ` 读片段提出可观测字段的修改建议，运行时 `U_R` 仅在**与固定规则兼容**时接纳；与结算事件矛盾的视觉证据记为渲染不一致，**不得推翻规则结果**。

### 2.5 领域适配
换新游戏只需换一份可执行游戏定义 `D_i`，共享运行时与同一冻结视频模型，**无需微调、无需游戏引擎**。

## 3. 实验设计与 Benchmark

### 3.1 WorldState-Bench（自建）
- **规模**：50 个反事实孪生对（100 条片段），覆盖 **49 个隐藏变量、21 个场景主题**（魔法学院、地牢、恋爱、密室、卡牌、侦探、回合制战斗等）。
- **构造**：FLUX.2 生成 1280×720 共享首帧；每帧经 **8 轮、6 维度 VLM 审计**，确保隐藏值不可见；规则以固定句式书写，两支结局均可从 DSL 推导。
- **隐藏变量族**：机制选择（42）、角色响应（6）、形态选择（2）；**触发类型**：cast（20）、gesture（42）、mechanism（26）、zone（12）。
- **Change-to-Comply 协议**：Change 判断动作是否产生可辨事件，Comply 判断事件是否满足该隐藏状态下的规则。
- **两种提示条件**：Rule-only（原始规则+动作）与 Rule+end（额外显式给出所需终态）。

### 3.2 指标
- 片段级：ENDFOLLOW、CNTABSENT、STRICT（= 二者同时满足）、UNCLEAR。
- 对级：**PAIRFOLLOW**（两孪生均正确）、**PAIRSTRICT**（两孪生均严格正确，主指标）、TWINCONTRAST（两结局是否不同）。
- 诊断：COPYPASTE、方向错误、泄漏（leakage-only）、branch gap、ΔSTRICT。

### 3.3 对比方法
- **11 个未包装后端**：4 个图生视频（Wan2.2 A14B、LongCat-Video 13.6B、HunyuanVideo 1.5、MiniMax-H3）+ 7 个交互式世界模型（LingBot-World v2、Echo-WM Flash、FantasyWorld、AlayaWorld、InSpatio-World、Astra、HY-WorldPlay）。
- **外部基准 WBench**（Ying et al., 2026）：与已报告 20 个模型及其类别均值比较，另做通道消融（4 种配置）。
- **人类审计**：17 个案例 × 3 系统 = 102 条片段做片段验证（3 名盲评）；25 对案例做强制二选一偏好对战（2 名盲评）。
- **多轮定性**：3 个真实 episode（15 / 29 / 11 轮，分别为城镇探索、恋爱叙事、Boss 对决）。

## 6. 主要结论与发现

- **未包装视频模型普遍不满足隐藏状态规则**：Rule-only 下最佳 PAIRFOLLOW 仅 **32%**（Wan2.2 与 MiniMax-H3）；显式给出终态（Rule+end）可把 MiniMax-H3 提到 **64%**，但 PAIRSTRICT 仅 **4%**——说明“说对结局”与“只呈现该结局”是两件事。
- **完整 harness 显著缩小差距**：同一冻结 MiniMax-H3 上达 **PAIRFOLLOW 92%、PAIRSTRICT 90%、TWINCONTRAST 96%**，人类偏好胜率 **98%**（无一次被基线在聚合规则下击败）。
- **增益可归因**：结局显式化 +32 点；规则执行 + 编译式参考通道 +28 点。
- **失效模式被量化**：Astra / HY-WorldPlay 在 Rule-only 下方向错误率高达 89% / 91%，但 CNTABSENT 达 96% / 95%——“不出现错误内容”不等于“出现正确内容”；HunyuanVideo 1.5 在 Rule+end 下泄漏率升至 34%。
- **跨游戏、免训练适配可行**：三种不同品类（探索 / 恋爱 / 对战）在 11–29 轮中维持 HUD 状态单调演化（体力 28→0→60、好感 47→75、Boss HP 128→0）。
- **外部基准不牺牲质量**：WBench 上 setting 71.1→87.2、interaction 77.7（对比中最高），画质 78.0、物理合理性 68.8 接近文本驱动类均值。
