## 摘要
游戏世界模型在实时交互式生成方面已取得快速进展。然而，动作控制仍主要作为特征条件来实现，模型需要从训练数据中学习每个动作应如何使视觉世界发生移动。这种形式与一大类平面相机世界（例如俯视和等距视角游戏）匹配不佳。在这些世界中，玩家运动会引起几何上明确定义的平面相机位移。我们观察到，在此类世界中实现空间一致控制的关键，是将每个动作的效果直接表示在世界坐标中。为此，我们提出 ActionRoPE，一种无参数的动作接口，将动作驱动的相机位移转换为世界坐标中的旋转位置。因此，对应同一世界位置的 token 在不同时间保持相同的位置地址。这些世界坐标进一步揭示了生成中的空间不对称性：初始观测覆盖的区域在几何上是已知的，而新显露的区域仍有待合成。因此，我们提出坐标条件噪声调度（Coordinate-Conditioned Noise Scheduling，CNS），根据这种已知—新显露结构为每个 token 分配去噪调度。它使已观测区域能够更早稳定，同时新内容可参照这些区域生成。与四种代表性动作条件机制相比，我们的方法更忠实地遵循指令运动，并且相较最强基线将重访漂移降低了 66%。同一接口可迁移至参数量从 1.3B 到 33B 的视频骨干网络，并可迁移到分布外场景。项目主页：https://teawhite.cn/ActionRoPE/。

## Abstract
Game world models have made rapid progress toward real-time interactive generation. Yet action control is still predominantly implemented as feature conditioning, leaving the model to learn from training data how each action should move the visual world. This formulation is poorly matched to a broad class of planar-camera worlds, such as top-down and isometric games. In these worlds, player motion induces a geometrically well-defined planar camera displacement. We observe that the key to spatially consistent control in such worlds is to represent the effect of each action directly in world coordinates. To this end, we introduce ActionRoPE, a parameter-free action interface that converts action-driven camera displacement into world-coordinate rotary positions. As a result, tokens corresponding to the same world location retain the same positional address across time. These world coordinates further expose a spatial asymmetry in generation: regions covered by the initial observation are geometrically known, while newly revealed regions remain to be synthesized. We therefore propose Coordinate-Conditioned Noise Scheduling (CNS), which assigns token-wise denoising schedules according to this known-new structure. It allows observed regions to stabilize earlier, while new content is generated with reference to them. Compared with four representative action-conditioning mechanisms, our approach follows the commanded motion more faithfully and reduces the revisit drift by 66% over the strongest baseline. The same interface transfers across video backbones from 1.3B to 33B parameters and to out-of-distribution scenes. Project Page: https://teawhite.cn/ActionRoPE/.

## 一、核心问题与研究动机

- **背景**：游戏世界模型（Genie、Oasis、Matrix-Game 等）已能实时生成可交互视频，但动作控制普遍采用**特征条件**范式：将动作编码为离散/文本 token、连续特征、AdaLN 调制或 cross-attention 输入，再由模型从数据中**隐式学习**“动作→视觉运动”的映射。
- **核心矛盾**：在**平面相机世界**（俯视、等距视角游戏）中，玩家移动会引发几何上明确定义的平面相机位移；动作的方向与幅度本可由标定后的几何直接决定，却被交给数据分布去拟合。结果是生成运动向训练分布回归，无法精确跟随指令。
- **更深层问题**：特征式动作表示**不提供显式世界坐标系**，模型无法判断当前 token 是否指向已观测过的世界位置，导致相机返回原地时场景错位、内容被重新生成（revisit drift）。
- **研究主张**：此类世界中的动作控制应被重新表述为**坐标对齐问题**，而非特征条件问题。

## 二、方法论

### 2.1 核心思想

- 把动作驱动的相机位移**直接写入视频 token 的旋转位置编码（RoPE）**，将“屏幕空间 RoPE”改为“世界空间 RoPE”，使**同一世界位置在不同时刻拥有相同的位置地址**。
- 世界坐标同时暴露了生成中的**空间不对称性**：首帧覆盖区域几何上已知，新显露区域待合成。据此提出**坐标条件噪声调度（CNS）**，让已知区域先稳定、新区域参照其生成。

### 2.2 ActionRoPE：动作作为世界坐标

- 标准时空 RoPE 位置为 `(k, i, j)`，`k` 为时间单元，`(i, j)` 为当前图像平面上的空间 token 坐标；每帧重置，故同一世界点随相机移动会得到不同地址。
- 世界坐标位置定义为 `(k, i + Δy_k/s, j + Δx_k/s)`，其中 `Δ_k = (Δx_k, Δy_k)` 为第 k 个时间单元的**累积相机位移**，`s` 为一个空间 token 对应的像素数（Wan2.2 中 `s = 32`）。
- 由于 RoPE 天然支持连续位置，位移**无需量化到 token 网格**；时间坐标保持不变。
- 关键性质：若静态物体从屏幕列 `j` 移到 `j − δ`，累积位移恰增加 `δ`，则两次观测被赋予同一坐标 `j`，跨帧注意力可**通过位置对齐**关联同一场景点，而非仅靠外观推断相对位移。
- 该接口**无参数**，不改变注意力架构。

### 2.3 已知 / 新显露区域划分

- 设 `Ω₀` 为首帧覆盖的世界坐标足迹，定义二值已知性场 `κ = 1[p_w ∈ Ω₀]`：`κ=1` 为已知区域，`κ=0` 为新显露区域。
- 该划分**完全由几何与动作轨迹决定**，训练与推理计算方式一致，无需辅助预测器。
- `κ` 通过一个**零初始化卷积**（或线性层）加入 patch embedding，仅 **0.015M 参数**，初始化时不影响预训练模型。

### 2.4 CNS：坐标条件噪声调度

- 基于底层 flow-matching 的 shift 调度 `σ(u; S) = Su / (1 + (S−1)u)`，为每个 token 分配独立 shift：`S_kij = S · (S_known/S)^κ`，再由 `u` 反解出 token 级噪声 `σ_kij`。
- `κ=0`（新区域）时退化为原调度；`κ=1`（已知区域）时使用更小的 `S_known < S`，**更早进入低噪声区间**。所有 token 共享端点 `σ(0)=0`、`σ(1)=1`，起点与终点一致，仅收敛速度不同。
- **训练**：按 token 各自噪声加噪，保持标准 rectified-flow 目标，timestep embedding 变为 token 相关（`t = 1000σ_kij`）；首帧作为干净锚点不计损失；新显露区域损失**加权 ×2**。
- **采样**：每步仅一次模型评估，各 token 沿自身调度推进，**不增加推理次数**；不 warp、不复制、不粘贴首帧内容。
- **实时化**：蒸馏为四步因果学生模型 + KV cache；因 RoPE 只依赖相对位置，ActionRoPE 可直接沿用到流式生成。

- **对比基线**（均在同一 Wan 骨干、同数据、同训练步数/seed 下重实现，输入相同的每帧相机位移）：
